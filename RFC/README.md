# 具体的な政策提言・仕様変更提案（Requests for Comments）

このディレクトリには、`docs/` 配下の構想を **具体的な政策提言・仕様の変更として提案する文書（RFC）** を置きます。
Issue が「問い・論点」を集める場所だとすれば、RFC は議論を経て **「こう変えるべきだ」という一つの提案にまとめたもの** です。

---

## 📌 RFC にするもの・しないもの

| RFC にするもの | Issue / 通常の PR で十分なもの |
|---|---|
| 法制度・補助制度の変更提案（例：認定制度の創設、容積率緩和の拡充） | 誤字脱字の修正、表現の改善 |
| 建築・設備仕様の要件の追加・変更（例：非常用電源の運転時間を 72時間→120時間へ） | 参考資料・事例の追加 |
| データ項目・API 仕様の追加・破壊的変更 | 問いかけ・問題提起（まずは Issue へ） |
| `docs/` の構成や本構想の基本方針に関わる変更 | |

---

## 📝 RFC の進め方

1. **Issue で論点を出す**：まずは Issue で問題提起し、方向性について意見を集めます。
2. **RFC を書く**：`RFC/NNNN-short-title.md` の形式でファイルを作成し、Pull Request を送ります。
   * `NNNN` は4桁の連番です（例：`0001-shirahige-certification.md`）。番号は PR 作成時点で未使用の次の番号を使います。
   * 下の「RFC テンプレート」をコピーして使ってください。
3. **議論（コメント期間）**：PR 上で議論します。コメント期間は原則として **2週間** とします。
4. **判断**：議論の結果を踏まえ、メンテナーがステータスを決め、PR をマージします（不採用の場合も記録として残すためにマージすることがあります）。
5. **反映**：採用された RFC の内容を `docs/` 配下に反映します。反映した PR には RFC 番号を記載します。

### ステータス

| ステータス | 意味 |
|---|---|
| `Draft` | 執筆中・議論中 |
| `Accepted` | 採用（`docs/` へ反映予定または反映済み） |
| `Rejected` | 不採用（理由を記載） |
| `Withdrawn` | 提案者による取下げ |
| `Superseded` | 後続の RFC に置き換えられた（後続の番号を記載） |

---

## 📄 RFC テンプレート

```markdown
# RFC NNNN: タイトル

- ステータス: Draft
- 提案者: @github-id
- 作成日: YYYY-MM-DD
- 関連: #Issue番号、docs/0X_xxx.md

## 📌 概要
<!-- 何を提案するのかを3行程度で -->

## 🔍 背景・課題
<!-- なぜこの変更が必要か。現状の問題、根拠となるデータ・事例 -->

## 💡 提案内容
<!-- 具体的な変更内容。制度案、仕様値、データ項目、条文案など -->

## ⚖️ 影響範囲
<!-- 関係する省庁・自治体・事業者・住民への影響、docs/ のどこを変えるか -->

## 💴 費用と効果
<!-- 概算の費用、期待される効果（仮定値の場合は明記） -->

## 🔁 代替案
<!-- 検討した他の案と、採用しなかった理由 -->

## ❓ 未解決の論点
<!-- 議論で決めたいこと -->

## 📚 参考資料
```
